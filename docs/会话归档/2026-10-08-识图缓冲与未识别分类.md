### 2. 识图缓冲：统一队列 + 全局冷却闸门，而不是给每个请求加 sleep

新建 `Core\ReverseQueue.cs`，包含两个类（现行代码）：

- **`ReverseWorkItem`**：一组（可能含多张近似重复图）只查一次识图；带 `GroupKey` / `Items` / `Result` / `Provider` / `TimedOut`。
- **`ReverseQueue.RunAsync`**：用 `Parallel.ForEachAsync` + `MaxDegreeOfParallelism = ReverseConcurrency` 把请求排队送出，**每个任务开始前先 `await _throttle.WaitAsync()`**，被限流时整条流水线一起等。
  - 队列自身异常时**不放弃**：日志写"识图队列异常，改为串行收尾"，然后串行补跑尚未完成的组（避免一次整理整批失败）。
  - 每 20 个（或最后一个）打印一次 `识图进度 d/total`，并向 UI 上报 `ProgressInfo{Phase="识图回退"}`。
- **`ReverseThrottle`（全局冷却闸门）**：任一请求被限流后，所有识图请求统一等待，冷却时间**指数增长（等级最多 6 级）但有上限**；优先采用服务端 `Retry-After`；**成功一次就把冷却等级回落一级**（避免长期按最大间隔等待）。等待时每 5 秒打印一次"识图冷却中，还需等待 X 秒"，让界面能看出正在冷却。

设计理由（代码注释原文）：

> 与 pixiv 元数据查询用线程池不同，SauceNAO / ascii2d 对频率非常敏感：这里用固定并发上限（默认 1 = 完全串行）+ 统一冷却，把识图请求排队送出，被 429/503 限流时全局暂停一段时间再继续，避免"越打越被拦"。

### 3. 一次识图调用只交给**一个**服务

`ReverseSearchService.SearchAsync` 改为：从 `ReverseOrder` 解析服务列表，记录 `start` 与 `lastUsed`（`LastProvider`），**被限流时整组重试同一个服务**，而不是把半截结果丢给下一个服务。代码注释原文：

> 一次识图调用只交给一个服务：被限流时整组重试同一个服务，而不是把半截结果再丢给下一个服务（那样既费配额又容易拿到低质量候选）。

### 4. 限流 ≠ 所有错误：区分永久性拒绝

SauceNAO 的 `status != 0` 里，**匿名拒绝属于永久性错误**（重试没用，不进入冷却），配额耗尽/限流才进入冷却。ascii2d 侧的 `!resp.Ok` 若判定为 `IsRejected` 也会 `_throttle.Block(...)`。同时新增 `LastProvider`（"上一次实际发起请求的识图服务"），未识别时写进报告便于排查。

### 5. 未识别分类：按原因归类 + 「未识别」文件夹

- 新增 `BuildUnresolvedKind(item)`，把原因归类为：`文件过大或无法读取` / `识图复核未通过` / （限流超时）/ `无 PID` / `识图无结果` / `pixiv 查询失败` / `目标路径过长`。

- 默认**开启** `MoveUnresolvedToFolder`，输出目录下建「未识别」文件夹，未识别文件按原名移入/复制，并记录原因。
